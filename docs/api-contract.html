Base URLs

Auth https://dev.bundlebox.ai/api/v1
Detection https://dev.bundlebox.ai/api/detection/v1
WebSocket wss://dev.bundlebox.ai/api/detection/v1
All detection endpoints require an Authorization: Bearer <token> header (JWT obtained from auth endpoints).

Call Sequence

  1. Authenticate — call one of the auth endpoints to get a JWT.
    ↓ save access_token
  2. Submit Video — upload a video for processing.
    Option A (recommended): Single call to POST /api/detection/v1/process-video
    Option B (chunked): POST .../upload/init → POST .../upload/{job_id}/file → POST .../upload/{job_id}/trigger
    ↓ receive job_id
  3. Listen for Progress — connect WebSocket for real-time updates.
    wss://dev.bundlebox.ai/api/detection/v1/ws/{job_id}?token=<jwt>
    ↓ receive progress events until type: "completed"
  4. Get Results — fetch final inventory and evidence images.
    GET /api/detection/v1/upload/{job_id}
    GET /api/detection/v1/upload/{job_id}/images/{name}

2. Detection APIs /api/detection/v1

All detection endpoints require Authorization: Bearer <token> header.
POST /api/detection/v1/process-video One-shot: upload video + start processing AUTH ▶
Recommended for mobile apps — single call does everything.

Request — multipart/form-data

Field Type Description
file file Video file (must have video/* content type) required*
gcs_url string GCS URL (gs://bucket/...) — alternative to file alternative*
scan_id string Becomes the job_id. Use a unique ID per scan. optional
room_id string Room identifier optional
room_name string Human-readable room name (e.g., "Living Room") optional

* Provide either file or gcs_url, not both.

Response 202

{
  "status": "queued",
  "job_id": "scan_123",
  "websocket_url": "/api/detection/v1/ws/scan_123",
  "result_url": "/api/detection/v1/upload/scan_123"
}

Errors

400 File must be a video / no input provided
401 Missing or invalid auth
POST /api/detection/v1/upload/init Initialize job (multi-step flow) AUTH ▶

Request — multipart/form-data

Field Type Description
job_id string Unique job identifier required
scan_id string Scan identifier optional
room_id string Room identifier optional
room_name string Human-readable room name optional

Response 202

{
  "status": "awaiting_upload",
  "job_id": "job_789",
  "websocket_url": "/api/detection/v1/ws/job_789",
  "result_url": "/api/detection/v1/upload/job_789",
  "upload_url": "/api/detection/v1/upload/job_789/file",
  "trigger_url": "/api/detection/v1/upload/job_789/trigger"
}
POST /api/detection/v1/upload/{job_id}/file Upload video file to existing job AUTH ▶

Request — multipart/form-data

Field Type Description

3. WebSocket /api/detection/v1/ws

WSS /api/detection/v1/ws/{job_id} Real-time processing progress AUTH ▶

Connection URL

wss://dev.bundlebox.ai/api/detection/v1/ws/{job_id}?token={jwt_token}
Auth is passed via ?token= query parameter (not header) since browsers don't support custom WebSocket headers.

Server → Client Messages

// Job initiated
{ "type": "initiated",  "progress": 0.01, "message": "Process initiated" }

// Progress updates (multiple)
{ "type": "processing", "progress": 0.25, "message": "Extracting frames..." }
{ "type": "processing", "progress": 0.50, "message": "Running detection..." }
{ "type": "processing", "progress": 0.75, "message": "Generating report..." }

// Completed — includes full result payload
{ "type": "completed",  "progress": 1.0,  "message": "Done", "result": { ... } }

// Error
{ "type": "error", "message": "Processing failed: ..." }

Client → Server

Message Response Purpose
"ping" {"type": "pong"} Keep connection alive (send every 30s)

Connection Lifecycle

  • Connection closes with code 1008 if auth fails
  • Auto-reconnect recommended with 3 second delay
  • Server sends pong in response to ping text frames
  • Connection stays open until client disconnects or job completes

4. Error Format & Codes

All error responses follow this format:

{
  "detail": "Human-readable error description"
}
Code Meaning When
400 Bad Request Validation error, invalid input, no file uploaded
401 Unauthorized Missing or invalid auth token
403 Forbidden Authenticated but not owner of this job/scan
404 Not Found Job, scan, or resource doesn't exist
409 Conflict Email already registered
410 Gone Deprecated endpoint (/trigger)
502 Bad Gateway Upstream service failure (Twilio, etc.)
503 Service Unavailable Required service not configured
