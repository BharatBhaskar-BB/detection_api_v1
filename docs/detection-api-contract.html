1. Overview

The Detection Pipeline API processes room-scan videos and returns a structured inventory of detected items with evidence images. Videos are processed asynchronously — submit a video, track progress via WebSocket, and retrieve results when complete.

Base URL https://dev.bundlebox.ai/api/detection/v1
WebSocket wss://dev.bundlebox.ai/api/detection/v1

2. Authentication

All endpoints (except /health) require a JWT token in the Authorization header. 

Authorization: Bearer <jwt_token>

JWT Token Format

Property Value
Algorithm HS256
Secret Shared JWT_SECRET (provided separately)
User ID claim sub

Expected JWT Payload

{
  "sub": "60c80bb7-9331-4b27-9d7a-8706b17ff929",
  "iat": 1776193468,
  "exp": 1776194368
}
The sub claim is used as the user identifier for ownership enforcement. Each job is bound to the user who created it — other users cannot access it.

WebSocket Authentication

WebSocket connections pass the JWT as a query parameter (browsers don't support custom headers on WebSocket): 

wss://dev.bundlebox.ai/api/detection/v1/ws/{job_id}?token=<jwt_token>

3. Call Sequence

Option A — One-shot (recommended for mobile)

  1. Upload & process
    POST /api/detection/v1/process-video with video file
    ↓ returns job_id
  2. Listen for progress
    wss://.../api/detection/v1/ws/{job_id}?token=<jwt>
    ↓ receive events until type: "completed"
  3. Get results
    GET /api/detection/v1/upload/{job_id}
    GET /api/detection/v1/upload/{job_id}/images/{name}

Option B — Multi-step (chunked upload)

  1. POST /api/detection/v1/upload/init → get job_id
  2. POST /api/detection/v1/upload/{job_id}/file → upload video
  3. POST /api/detection/v1/upload/{job_id}/trigger → start processing
  4. Connect WebSocket + poll results (same as Option A steps 2–3)

4. Endpoints

GET /api/detection/v1/health Health check NO AUTH ▶

Response 200

{
  "status": "ok",
  "service": "pipeline_backend"
}
POST /api/detection/v1/process-video One-shot: upload video + start processing AUTH ▶
Recommended for mobile — single call uploads the video and queues processing.

Request — multipart/form-data

Field Type Description
file file Video file (video/* content type) required*
gcs_url string GCS URL (gs://bucket/...) — alternative to file alternative*
scan_id string Becomes the job_id. Use a unique ID per scan. optional
room_id string Room identifier optional
room_name string Human-readable room name (e.g., "Living Room") optional

* Provide either file or gcs_url, not both.

Response 202

{
  "status": "accepted",
  "job_id": "scan_123",
  "websocket_url": "/api/detection/v1/ws/scan_123",
  "result_url": "/api/detection/v1/upload/scan_123",
  "scan_id": "scan_123",
  "room_id": null,
  "user_id": "60c80bb7-...",
  "video_id": 1,
  "room_name": null
}

Errors

400 File must be a video / no input provided
401 Missing or invalid token

5. WebSocket

WSS /api/detection/v1/ws/{job_id} Real-time processing progress AUTH ▶

Connection

wss://dev.bundlebox.ai/api/detection/v1/ws/{job_id}?token={jwt_token}

Server → Client Messages

// Job initiated
{ "type": "initiated",  "progress": 0.01, "message": "Process initiated" }

// Progress updates (multiple)
{ "type": "processing", "progress": 0.25, "message": "Extracting frames..." }
{ "type": "processing", "progress": 0.50, "message": "Running detection..." }
{ "type": "processing", "progress": 0.75, "message": "Generating report..." }

// Completed — includes full result payload
{ "type": "completed",  "progress": 1.0,  "message": "Done", "result": { ... } }

// Error
{ "type": "error", "message": "Processing failed: ..." }

Client → Server

Message Response Purpose
"ping" {"type": "pong"} Keep connection alive (send every 30s)

Connection Lifecycle

  • Connection closes with code 1008 if auth fails
  • Auto-reconnect recommended with 3 second delay
  • Server sends pong in response to ping text frames
  • Connection stays open until client disconnects or job completes

6. Error Format & Codes

All error responses follow this format:

{
  "detail": "Human-readable error description"
}
Code Meaning When
400 Bad Request Invalid input, missing file, bad job_id format
401 Unauthorized Missing or invalid JWT token
403 Forbidden Valid token but not the owner of this job/scan
404 Not Found Job, scan, or image doesn't exist
410 Gone Deprecated endpoint (/trigger)
